# Writing

## Code comments

English, and short. A comment explains why something is the way it is when the
code does not already say so. It does not restate the code.

```bash
# These take PEM contents, not paths. A path fails with "Invalid certification data".
```

That is the shape: a fact the next person would otherwise learn the hard way.

The same goes for workflow step names and any string the repository prints.

## Documentation

No em dashes. Use commas, periods, colons or parentheses.

Do not explain the document to the reader. If it defines its terms, that is
visible. Sentences like "this is written so that anyone can follow it" are
padding.

Quote sources. Any claim about a paper or an external system carries a short
quote and a section reference, not a paraphrase presented as fact.

Do not overpromise. Write "verifies that" rather than "proves that". Mark what
is unverified as unverified.

Thesis documents for the course are written in Spanish. Everything inside this
repository is written in English.
